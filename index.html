第一章 :: INTRODUCTION

系統概述與目的

系統簡介
  • 以瀏覽器為平台的指令式文字冒險與解謎遊戲。
  • 玩家輸入指令，閱讀信件與故事文件，並調查劇情物件。
  • 使用黑白主題、文字動畫及音效營造探索氛圍。
文件目的與範圍
本文件說明系統架構、主要模組、操作流程、介面與資料設計，供專案成員、開發人員及測試人員參考。 目前已有的功能與未來規劃會分開說明；完整存檔、讀檔及後端服務屬於未來規劃。

第三章 :: COMMAND DESIGN

指令介面與處理設計

目前主要指令
指令功能
simple開啟說明信件。
01_GR_1開啟故事文件。
HELP_67開啟 HELP_67 文件。
inspect_ri開啟山脊旅店調查內容。
inspect_sh開啟 Shiminaseo 調查內容。
list查看已解鎖內容。
theme、black、white切換或指定黑白主題。
name、6、7變更玩家或角色名稱。
title／tittle自訂列表中的資料夾名稱。
back、exit、Esc返回終端機或前一畫面。
指令處理流程
  1. 玩家於終端機或列表頁輸入指令。
  2. 系統清除前後空白並辨識指令名稱與參數。
  3. 依指令更新畫面、名稱、主題或解鎖狀態。
  4. 需要保存的部分資料寫入 localStorage。
  5. 若指令無效或格式錯誤，顯示提示訊息。
完整的 save／load 指令目前尚未實作；若未來加入，需連接本機存檔或後端 API。

第三章 :: DATA DESIGN

資料保存與未來存檔設計

目前本機保存資料
localStorage Key用途
cli_folder_names自訂資料夾名稱。
cli_unlocked_letters已解鎖的信件與文件項目。
cli_user_name_v2玩家名稱。

cli_used_names曾使用過的名稱。

這是部分狀態的本機保存，不等同於完整存檔／讀檔，也無法跨瀏覽器同步。

未來雲端存檔概念
SaveData
├─ version       存檔格式版本
├─ savedAt       最後保存時間
├─ playerNames   玩家與角色名稱
├─ unlockedItems 已解鎖內容
├─ readChapters  已讀章節
└─ settings      主題及其他設定
  1. 瀏覽器首次連線時，後端建立匿名識別碼。
  2. 識別碼以 Cookie 儲存在該瀏覽器。
  3. 前端透過 HTTPS API 傳送或讀取遊戲進度。
  4. 後端依匿名識別碼存取 PostgreSQL 中的進度。

匿名 Cookie 只能辨識目前瀏覽器，不代表登入或真實身分驗證；清除 Cookie 或更換裝置可能無法找回進度。

第四章 :: UI / UX DESIGN

介面與使用者體驗設計

終端機首頁
顯示開場文字動畫、玩家名稱與指令輸入欄，作為主要操作入口。
故事與信件
以文件或信件版面呈現劇情，部分文字可點擊調查，並支援逐字顯示效果。
解鎖列表
將已開啟的故事項目依類別整理，玩家可從列表再次進入內容。
畫面概念：終端機
┌────────────────────────────┐
│                  [主題切換] │
│                            │
│       Welcome Player!      │
│                            │
│ > 輸入指令...              │
│                            │
│ 操作提示                   │
└────────────────────────────┘
設計原則
  • 黑白主題維持一致的復古終端機風格。
  • 指令輸入與按鈕操作並行，方便不同使用習慣的玩家。
  • 使用提示文字處理錯誤，避免彈窗中斷閱讀。
  • 音效或動畫失敗時，仍可繼續閱讀與操作。
第五章 :: QUALITY & SECURITY

非功能性需求與安全性

非功能性需求
  • 可用性：提供清楚的指令提示與返回方式。
  • 穩定性：錯誤指令或音效失敗不應造成遊戲中斷。
  • 相容性：以現代瀏覽器為主要執行環境。
  • 可維護性：未來將大型元件拆分為不同功能模組。
  • 擴充性：可新增故事內容、指令與互動物件。
安全性與異常處理
  • 目前沒有玩家帳號、密碼或登入驗證。
  • 若採用匿名 Cookie，後端需檢查請求與資料格式；Cookie 不代表玩家真實身分。
  • 若未來使用後端，前後端通訊應採 HTTPS。
  • 讀取本機 JSON 發生錯誤時，使用預設狀態繼續遊戲。
  • 音效無法載入或播放時，略過音效，不影響遊戲流程。
  • 未知指令或格式錯誤時，在介面顯示提示訊息。
本系統目前為單人瀏覽器遊戲，沒有高併發需求，因此不規劃 Redis 或負載平衡。若未來加入雲端服務，再依使用規模評估。
第六章 :: STATUS & FUTURE PLAN

目前成果與未來規劃

目前已有功能
  • React、TypeScript 與 Vite 建立的瀏覽器遊戲。
  • 終端機風格指令輸入及多個故事畫面。
  • 黑白主題切換、開場動畫與信件逐字效果。
  • 故事物件調查及已解鎖內容列表。
  • 玩家／角色命名與部分 localStorage 保存。
  • 指定章節的雨聲、敲門聲等音效效果。
未來開發項目
  • 完整存檔、讀檔與多存檔槽。
  • 以 Node.js、Express 建立後端 API。
  • 以 PostgreSQL 保存匿名玩家進度。
  • 設計匿名 Cookie 識別及存檔版本檢查。
  • 擴充故事章節、互動事件與任務內容。
  • 拆分指令、故事資料、狀態與儲存模組。
  • 增加自動化測試與錯誤情境測試。
開發順序建議

第一階段完成故事與遊戲流程；第二階段整理前端模組並加入本機完整存檔；第三階段再建置後端、資料庫與匿名玩家進度保存。
