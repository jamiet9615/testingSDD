系統概述與目的（Introduction）

系統簡介
  • 以瀏覽器為平台的指令式文字冒險與解謎遊戲
  • 閱讀信件與故事文件、調查劇情物件，並逐步探索遊戲內容
  • 黑白主題、文字動畫及音效，營造沉浸式的閱讀與探索體驗
目的與範圍
說明系統的整體架構、主要模組、操作流程、介面與資料設計，涵蓋遊戲前端、指令處理、故事內容、解鎖列表、玩家設定、音效動畫、存檔與讀檔。

系統架構設計（System Architecture）

系統目前採用瀏覽器端前端架構，使用 React 建立畫面，TypeScript 撰寫程式，Vite 負責開發與建置。遊戲主要邏輯在瀏覽器內執行，部分設定與解鎖資料使用 localStorage 保存。目前沒有後端伺服器或資料庫。

第三章 :: 相依視圖 (DEPENDENCY VIEW)

單次指令處理之資料流程圖

指令執行生命週期
  1. 玩家輸入： 玩家於 Terminal 輸入框鍵入指令並按下 Enter。
  2. 傳遞與解析： ui.js 傳送字串至 parser.js 進行正則分析與清洗。
  3. 狀態更新： 若語法正確，由 state.js 變更遊戲狀態並寫入 LocalStorage。
  4. 錯誤轉向： 若語法錯誤，轉交 errorHandler.js 產生錯誤訊息。
  5. 介面輸出： ui.js 啟動打字機效果印出結果，並由 audio.js 觸發音效。

指令解析邏輯與正則表達式 (parser.js)

指令語法與需求對照表
指令格式範例 功能說明與邊界條件 需求編號
simple 獲取當前章節關鍵提示訊息 F-02
list 列出當前已解鎖之道具、文件與章節資料夾清單 F-03
inspect [target] 調查特定場景或物品細節（如 inspect note_01） F-04
05_HO_05 / 05_HO_123 章節/地點/人物劇情觸發指令（多人代號須依小到大排序） F-05
name [P1~P5] [newName] 重新命名角色暱稱（底層 ID 維持固定不變） F-06
save [slot] / load [slot] 手動儲存或讀取指定槽位之遊戲進度 (1~5 號槽位) F-08
解析器核心程式邏輯
function parseCommand(rawInput) {
  const cleaned = rawInput.trim();
  if (!cleaned) return { type: 'EMPTY' };
  
  // 比對劇情複合指令 (例如 05_ho_123)
  const storyMatch = cleaned.toLowerCase().match(/^(\d{2})_([a-z]{2})_(\d+)$/);
  if (storyMatch) {
    const [_, chapter, location, who] = storyMatch;
    // 驗證多人代號是否嚴格升冪排序 (例如 123 合法，321 不合法)
    if (who.length > 1 && !isAscending(who)) {
      return { type: 'INVALID_ORDER' };
    }
    return { type: 'STORY', args: { chapter, location, who } };
  }

  const tokens = cleaned.split(/\s+/);
  return dispatchStandardCommand(tokens);
}
第四章 :: 元件詳細設計 (STATE)

狀態機邏輯與解謎演算法 (state.js)

人格暱稱與代號解耦設計
系統底層固定維護 5 位人格代號（P1 ~ P5），玩家輸入 name P1 自訂名稱 時僅變更 UI 渲染欄位，不會影響底層邏輯與劇情觸發條件（F-06-04）。
符文連線序列對照
第 13 幕解謎機制要求玩家按嚴格順序連線房間：
301 (天台) ➔ 204 (命案現場) ➔ 205 (密室) ➔ 103 (診斷室)
若順序不符則陣列自動重置，避免玩家暴力列舉突破。
狀態分派邏輯
function updateGameState(cmd) {
  switch(cmd.type) {
    case 'STORY':
      if (!canTrigger(cmd.args)) return ErrorHandler.trigger('NOT_READY');
      GameState.currentChapter = cmd.args.chapter;
      GameState.currentLocation = cmd.args.location;
      advanceStoryNode();
      break;

    case 'RENAME':
      GameState.names[cmd.args.target] = cmd.args.newName;
      break;
  }
  // 每次有效指令皆自動觸發 LocalStorage 寫入
  autoSaveToLocalStorage();
}
第五章 :: 資料庫與資料結構設計 (DATA DESIGN)

LocalStorage 儲存模型與驗證機制

存檔資料防護與防呆設計 (NF-06)
  • Schema 結構校驗： 讀取存檔時先檢查欄位完整性，避免因舊版存檔或人為修改造成程式報錯。
  • 容錯還原機制： 當偵測到存檔 JSON 解析失敗時，自動拒絕讀取並保留當前記憶體狀態，防止系統崩潰。
  • 無痕模式防護： 當瀏覽器停用 LocalStorage 時，使用 try...catch 捕獲異常並跳出友善提示，維持遊戲基本運作。
第四章 :: 元件詳細設計 (UI & ERROR)

介面渲染與防呆錯誤處理設計

Terminal 控制與打字機效果 (ui.js)
  • 逐字印出 (F-10-02)： 採用 requestAnimationFrame 實現平滑打字機動畫。
  • 跳過機制 (F-10-03)： 當文字仍在繪製時按下 Space 或 Enter 鍵，即時清除 Timer 並展開全文字。
  • 歷史對話框 (F-07)： 使用獨立面板顯示 log/history，避免主文字區域混亂。
錯誤捕捉與驚悚提示 (errorHandler.js)
錯誤型態 系統處理機制與訊息提示
INVALID_CMD 回傳「黑暗中沒有回應，請檢查輸入指令。」
NO_OBJECT 回傳「你仔細觀察了四周，並沒有找到該物件。」
ORDER_ERR 回傳「聲音混亂...多人對話順序必須由小到大。」
全站使用全局 window.onerror 與 try...catch 攔截，完全不採用瀏覽器原生 alert() 彈窗，保障遊戲沉浸感。
